## Design Context

### Users
Engineering and security teammates use the same multi-tenant workspace. Their jobs are to connect GitHub repositories or local project folders, run Maven/npm analysis, trace dependency inventory and OSV findings to source evidence, and coordinate review and reporting. They work with real project data and permission-scoped repositories; no sample metrics or records are acceptable.

### Brand Personality
Clear, credible, focused. The interface should lower uncertainty and help people decide what to inspect next without overstating what a scan proves. Copy is concise, plain Spanish by default, and technically precise.

### Aesthetic Direction
Keep the established Evidence Observatory palette and dark default, with the user-selected light/system options. Preserve IBM Plex Sans, local SVG icons, and compact operational controls. Avoid template-like sameness: give each workflow its own information shape (risk review, data catalogue, analysis history, repository intake, document library, account administration) while retaining shared navigation and component behavior. Do not copy the layouts or assets of the references. Prefer task-specific composition over repeated card grids; use accent colors sparingly and semantic colors consistently.

### Implementation Defaults
Existing Angular 22 standalone application, Angular Material/CDK, TypeScript, RxJS/Signals, Sass, current forms, API adapters and navigation. Reuse current components and tokens. No framework migration, backend/API/database/auth changes, invented data, or unnecessary dependencies.

### Design Principles
1. Vary layout to match the task; keep navigation and shared controls predictable.
2. Put provenance, coverage, and the next available action beside the evidence they describe.
3. Establish hierarchy with grouping and spacing before adding color or decoration.
4. Preserve every action, permission boundary, loading/error/empty state, and real data binding.
5. Validate keyboard, contrast, responsive reflow, reduced motion, and existing user journeys before calling a screen complete.
